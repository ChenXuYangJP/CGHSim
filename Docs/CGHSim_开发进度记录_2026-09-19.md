### 11.2 有符号位置与 SLM 法线

SLM 局部 **+X 是光学法线**，有效面位于局部 YZ 平面；+Y 为横向，+Z 为纵向。对于世界位置 `P`、SLM 原点 `O`（两者以 UE 厘米表示）及世界空间单位法线 `N`，快照中的深度为：

```text
X_m = dot(P_cm - O_cm, N) × 0.01
```

沿法线一侧为正 X，反向一侧为负 X，平面上为零；Y/Z 同样保留相对局部轴的正负号。固定世界位置时，SLM 法线反向会自动使 X 反号；法线倾斜时按旋转后的轴投影，不使用世界 X 差值或无符号距离。目标、相机光学位置和重建光源位置使用同一约定，光源传播方向与相机前向也随 SLM 坐标轴转换。

转换使用 `InverseTransformPositionNoScale` / `InverseTransformVectorNoScale`，忽略 SLM Actor 缩放，保留真实物理距离。`ValidateScene()` 仍会拒绝非单位光学根缩放；忽略缩放不代表该配置通过物理验证。

### 11.3 更新触发与使用方式

Workbench 暴露临时、只读的 `SceneDescription` 和 `bSceneDescriptionComplete`。编辑器通过 `OnObjectPropertyChanged`、`OnObjectTransacted` 回调更新；组件观察覆盖关联 Actor 的根变换及 Camera 的 `OpticalReference` 变换。引用替换、Actor 销毁和重新绑定均会刷新观察关系并重建快照，防止残留旧值。

运行时通过 `TG_PostUpdateWork` Tick 捕获直接写入参数的变化。需要在同一帧中立即消费新值时，先显式调用 `UpdateSceneDescription()`。缺失引用对应的描述恢复为零值，缺失 SLM 时无法建立局部坐标系，目标列表为空；单个目标引用缺失时保留数组位置并置零。

## 12. 网格目标、选择性能与 SLM 相位预览（2026-09-21 补充）

### 12.1 网格目标资源与自动更新

`ACGHTargetActor` 现在同时支持 Point 和 Mesh。Mesh 使用独立的 `GeometryMesh` 组件，Point 继续使用数学点的振幅和相位，忽略网格与采样参数，并清空不再使用的几何、点云数组。

已整理 `FCGHTargetDescription`、`FCGHMeshGeometryResource`、`FCGHPointCloudResource` 和 `FCGHObjectPoint` 的反射结构、声明顺序及默认值。一个目标的描述、网格和点云使用同一个 `ResourceId`，用匹配的 `Revision` 标识同一代数据。ID 属于当前进程中的 Actor 实例；创建另一个实例会得到不同 ID，不能作为跨会话持久资源标识。

| 配置或资源 | 当前行为 |
| --- | --- |
| `GeometryMesh` | 读取 Static Mesh 的 LOD 0 顶点、三角形索引、法线和 UV0；Nanite 资产使用回退网格 |
| `SLM` | 可显式指定；未指定时由关联 Workbench 提供。不同参考坐标系不能混用，同一缓存不能被另一个 Workbench 强行切换 |
| `SliceCount` | 默认 32；沿目标原点指向 SLM 原点的轴等距分层，在每层中点取截面 |
| `PointSpacingMm` | 默认 5 mm；约束缩放后的截面轮廓采样间距 |
| `MaxPointCount` | 默认 100,000；超限时报错并清空结果，不返回不完整的点云 |
| `FCGHObjectPoint` | 包含局部米制位置、插值法线/UV、目标振幅及相位 |

采样对象是三角形与截面的相交轮廓，不填充截面内部。重合点合并，退化三角形跳过；共面网格保留边界并去掉内部三角剖分对角线。该采样尚不处理遮挡、材质光学响应或传播计算。

Construction、BeginPlay、变换/属性/事务通知及 Tick 输入比较负责更新。Actor 缩放、网格组件偏移/旋转/缩放、模型替换、采样参数、振幅/相位和 SLM 参考变化都会发布新版本；输入不变时保持原版本。`UpdateTargetResources()` 用于同帧立即读取，`RebuildTargetResources()` 用于自定义运行时网格修改后的强制重读。失败时通过 `bResourcesValid` 和 `ResourceError` 给出原因，清除旧数组并更新版本，避免继续使用过期数据。

Workbench 从 Actor 复制轻量描述和版本引用，不把大块几何数组重复装进场景快照；目标资源无效或 SLM 参考不匹配时，场景快照不完整。Mesh 目标允许非均匀和镜像缩放，SLM/Camera/Light 的根缩放仍须为 `(1,1,1)`。

### 12.2 点云显示尺度与选择性能

开启 **Show Point Cloud** 会隐藏 `GeometryMesh` 并显示采样点，关闭后恢复网格显示。`DebugPointSize` 表示屏幕像素大小，不代表点的物理尺寸；屏幕上的点标记可能使轮廓看起来更粗。源网格 LOD 0/Nanite 回退几何与视口最终网格也可能存在差别，应同时检查资源是否已刷新。

几何和点云已经包含 Actor/网格组件的实际缩放及组件偏移，单位为目标刚性局部坐标中的米。点云显示组件使用绝对单位缩放，显示时只把米换成厘米并应用目标平移/旋转，不能再次乘 Actor 缩放。非均匀缩放的法线使用逆转置，镜像变换同步修正三角形绕序；已有回归验证其世界坐标重建和法线方向。SLM 物理尺寸同样与屏幕预览尺寸分开：像素间距控制物理有效面，不用于放大预览像素网格。

针对“每次选择目标都很慢”的反馈，确认选择本身没有推进资源版本；开销来自 Details 对大块数组创建属性树。修复后 Details 只显示 `MeshVertexCount`、`MeshTriangleCount`、`PointCount`、描述/版本和资源状态。完整网格和点云仍可通过 C++、Blueprint 和反射读取，但大数组不再展开到 Details，也不写入 Undo 事务。派生描述与状态同样排除事务保存，避免撤销时元数据与缓存内容不同步。

实际编辑器选择和 Details 属性树回归使用 3,264 个缓存点，检查重复选择/取消选择不会重建资源、改变 Revision 或替换缓存内存，且面板仍显示正确的计数。此阶段的 14 项 CGH 自动化测试及 Editor/Game 构建已通过，报告位于 `Saved/Automation/CGHTargetSelection`。

### 12.3 SLM 相位存储与发布接口

新增 `Types/CGHSLMPhasePattern.h` 中的 `FCGHSLMPhasePattern`：`ResolutionX/Y`、`TArray<double> PhaseRad` 和 Actor 管理的 `Revision`。相位单位为弧度，按 `PhaseRad[row * ResolutionX + column]` 存储，row=0 为顶行；行列与 SLM 局部空间轴的对应关系见第 13 节及 [SLM 像素坐标约定](SLM_Pixel_Coordinates.md)。默认 SLM 仍为 `4096 × 4096`、`8 um`，有效面为 `32.768 × 32.768 mm`；默认相位数组为空，不分配整幅零值数据，也不冒充已计算的全息图。

| 接口或状态 | 用途与约定 |
| --- | --- |
| `SetPhasePattern()` | 接受与当前 SLM 分辨率完全一致、数量精确且全部有限的相位数组；成功后由 Actor 持有副本并管理版本，忽略传入 Revision |
| `GetPhasePattern()` / `GetPhasePatternRevision()` | C++ 只读引用访问和版本检查，避免无意复制大数组 |
| `GetPhasePatternCopy()` | Blueprint 获取独立副本；修改副本不能绕过 setter 修改内部数据或跳过版本更新 |
| `HasValidPhasePattern()` | 检查当前数据是否仍匹配当前像素网格 |
| `SynchronizePhasePattern()` | 同帧消费前检查分辨率变化，清除不再匹配的数据；编辑器/运行时 Tick 也执行该检查 |
| `ClearPhasePattern()` | 清空数据并立即释放预览纹理；重复清空未变化的空状态不会增加版本 |
| `GeneratePreviewPhaseRamp()` | 显式生成每行相同的 `2*pi*column/ResolutionX` 测试斜坡，并设置 `bIsPreviewPhasePattern`；不执行 CGH 求解 |

无效输入返回 false，通过 `PhasePatternError` 说明原因，同时保留上一份有效数据和版本。像素间距变化与 **Refresh Visualization** 保留有效相位；任一分辨率变化会清空不匹配的数据并增加版本。相同相位重新发布、重复选择 Actor 不增加版本；外部发布会清除“测试斜坡”标记，即使数据恰好相同。

状态初始为 `GenerationState = NotImplemented`、`bHasPhaseData = false`；成功发布数据后为 `Ready`，这里只表示“已有有效相位数据”，不表示光学求解器已经实现。清空后恢复初始状态。相位数据为 Transient，不随地图保存；内部存储不暴露可变 Blueprint 成员，也不出现在 Details 数组树或 Undo 事务中。

输入上限为每轴 16,384 像素、总计 67,108,864 像素；预览还受显卡最大纹理尺寸限制。较大分辨率需要相应的 CPU/GPU 内存，当前限制不代表所有尺寸均已进行性能验收。

### 12.4 选中 SLM 时的原生相位预览

`UCGHSLMPreviewComponent` 接入 UE 原生 selected-actor picture-in-picture 机制，选中 SLM 即可显示相位面板，不需要 Camera 或 SceneCapture。空状态显示 **No phase pattern**。在 **CGH > Phase** 点击 **Generate Preview Phase Ramp** 可检查显示，面板明确标为 **Preview test ramp**；使用 **Clear Phase Pattern** 返回空状态。

该面板遵循编辑器 **Preview Selected Cameras** 开关，**Camera Preview Size** 调整面板尺寸。完整图像保持像素网格纵横比并按需留边，面板尺寸不会改变 SLM 分辨率、物理像素间距或存储的相位。编译后需重启编辑器以加载新的原生预览组件；现有 `BP_CGHSLM` 可以继承该组件，无须重新生成 Blueprint 资源。

预览纹理与 SLM 分辨率一一对应，使用 BGRA8、最近邻采样和禁用 gamma 转换的线性灰度显示。相位先环绕到 `[0, 2*pi)`：0 和整周期为黑色，pi 为中灰，接近 2*pi 为白色；负相位按同一规则环绕。纹理仅在数据版本或网格尺寸变化后更新，重复选择复用缓存。预览组件与纹理只用于编辑器，运行时仍保留相位数据和发布接口。

## 13. SLM 像素坐标约定与代码审查（2026-09-21）

以 [SLM 像素坐标约定](SLM_Pixel_Coordinates.md) 为权威记录，统一相位数组、二维图像与 SLM 局部空间之间的关系。保留已有公开字段名，X/Y 后缀表示图像/像素网格轴，不直接表示 Actor 的空间 X/Y 轴。

| 网格字段 | 图像含义 | SLM 局部空间含义 |
| --- | --- | --- |
| `ResolutionX`、`PixelPitchXM`（编辑参数 `PixelPitchXUm`） | 水平列数与间距 | 横向沿 Y，column 增加时向 +Y |
| `ResolutionY`、`PixelPitchYM`（编辑参数 `PixelPitchYUm`） | 垂直行数与间距 | 纵向沿 Z，row 增加时向 -Z |

SLM 局部 +X 为光学法线，+Y 为规范图像中的右方，+Z 向上。像素中心位于 X=0 平面，原点位于整幅有效面的中心：

```text
PhaseRad[row * ResolutionX + column]
column ∈ [0, ResolutionX - 1]
row    ∈ [0, ResolutionY - 1]

X = 0
Y = (column - (ResolutionX - 1) / 2.0) * PixelPitchXM
Z = ((ResolutionY - 1) / 2.0 - row) * PixelPitchYM
```

中心坐标使用米；公式必须采用浮点除法，避免偶数分辨率发生半像素偏移。row=0 位于上侧，column=0 位于左侧；有效宽高仍为分辨率乘间距，边缘距离最外侧像素中心半个像素间距。

规范正面图保留用户指定的“从 +X 一侧朝 -X 看，+Y 显示向右，+Z 显示向上”，将其明确定义为二维图像显示约定。普通 UE 相机从 +X 一侧朝 -X 看、并保持 +Z 朝上时，其屏幕右方实际为 SLM 的 -Y；要让该相机图像匹配规范正面图，需水平镜像。这一点由本地 UE 旋转矩阵和相机视图矩阵确认。当前相位控件直接绘制数组，场景中的普通相机仍保持物理视角；本次不翻转相位数据或修改 Actor 坐标轴。

源码审查确认：相位存储、灰度上传/绘制及最近邻重采样保持行列顺序；有效面的宽度沿局部 Y、高度沿局部 Z；SI 场景导出使用相同的 SLM 刚性局部坐标。未发现这些路径存在轴交换或行方向翻转。当前尚无像素中心光学求解器，也没有将相位贴到世界空间 SLM 网格的实现；后续实现必须遵守上述中心公式，并单独处理物理相机与规范图像的镜像关系。

## 14. CPU 单点聚焦参考求解器（2026-09-21）

本节记录首个光学计算实现；第 12、13 节中的“求解器未实现”和“像素中心尚无数值消费者”描述保留为对应时间的历史记录。当前接口、使用步骤与完整假设见 [CPU PointFocus 求解器](CGH_PointFocus_Solver.md)。

### 14.1 传播约定与数值范围

明确将传播符号写入求解输入：`U(r) ∝ exp(+i*k*r)`，`k = 2*pi/WavelengthM`。平面波入射相位为 `phi_inc(p)=InitialPhaseRad+k*dot(DirectionSLM,p)`，每个像素输出 `wrap_[0,2*pi)(TargetPhaseRad-k*r-phi_inc(p))`，因此叠加入射相位和传播相位后，目标处相位均等于目标相位模 `2*pi`。结果元数据同样携带传播约定，Actor 拒绝与请求不一致的结果。未来 CUDA、FFT 或网络库必须保留该约定，或在边界处明确转换，不能默默改变符号。

像素中心严格采用第 13 节公式：X=0，Y=`(column-(ResolutionX-1)/2.0)*PixelPitchXM`，Z=`((ResolutionY-1)/2.0-row)*PixelPitchYM`，按 `PhaseRad[row*ResolutionX+column]` 存储。计算使用米、弧度和 `double`；用 `std::hypot` 求三维距离，避免不必要的平方中间溢出。

第一版只接受一个 `TargetType=Point` 的 `ACGHTargetActor` 和 phase-only SLM。目标必须位于 SLM 平面外，即局部 X 不为零；正负 X 均可作为有符号输入，当前标量距离模型没有选择物理器件的出光侧。分辨率、间距和波长须合法且正值，位置/相位/传播计算须有限；Mesh、多目标及非法输入返回失败，不发布部分数组。

第一版只支持 **PlaneWave**，读取光源波长、`InitialPhaseRad` 和单位传播方向 `DirectionSLM`，补偿斜入射在 SLM 上形成的相位斜坡。初相位参考点固定为 **SLM 原点**；光源 `PositionSLMM` 不参与计算，移动光源 Actor 不会改变参考点。沿 ±X 法向入射且初相位为零时，公式退化为原来的 `wrap(TargetPhaseRad-k*r)`。PointSource 或未知光源类型明确失败。

初相位和方向各分量必须有限，方向非零且满足 `abs(DirectionSLM.SizeSquared()-1)<=1e-6`。光源 Amplitude 必须有限且非负，PolarizationAngleRad 必须有限；这两个参数虽被校验，但不影响当前标量 phase-only 结果。目标振幅/旋转、相机参数也不参与计算；没有 `1/r` 振幅权重、偏振响应模型、传播图或传感器模拟。PointFocus 不要求 Camera 引用，但 Workbench 的全场景完整性/验证仍包含 Camera。

### 14.2 Actor、后端与缓冲区

新增 `ACGHSolverActor`，默认 **CPU / PointFocus**，按钮 **Generate Phase Pattern** 和 **Cancel Solve**，可选 **Auto Solve** 默认关闭。作业状态为 `Idle`、`Queued`、`Running`、`Ready`、`Failed`，并暴露请求编号、状态消息和计算耗时。自动模式只响应实际参与计算的输入或引用变化，包括光源初相位、方向和类型；合法的光源位置/振幅/偏振改变不触发重算，非法字段仍会在提交和发布前校验中被拒绝。取消后不会立即重算未变输入。临时缺失的引用恢复后可自动重试，未变的非法数值（包括 NaN）不会反复创建任务。

数据流为 UE Actor → Workbench 的 `FCGHSceneDescription` → `FCGHSolverInput` 快照 → `UCGHSolverBackend` → `FCGHSolverResult/FCGHSLMPhasePattern` → `SetPhasePattern()` → SLM 预览。`UCGHCPUSolverBackend` 在 UE 线程池执行纯数值核心；worker 持有不可变的自有输入副本、取消/完成原子标志和输出缓冲，不访问任何 Actor/UObject。

每个 Solver 最多有一个运行任务和一个最新待处理请求。新请求替换待处理输入并协作取消旧任务，等待旧 worker 实际结束后再启动下一个，避免同时分配多幅输出。Actor 在编辑器和运行时 Tick 非阻塞轮询；读取结果前检查完成标志，开始待处理任务和发布结果前核对输入、Actor 引用及 SLM 相位版本，防止目标移动、参数修改、引用替换/删除或人工加载/清空相位后被旧结果覆盖。

`EndPlay` 取消并释放任务、恢复 `Idle`；后端与作业元数据使用 `DuplicateTransient`，复制 Actor 和 PIE 副本不会继承旧任务或状态。成功结果在 game thread 通过新增的 C++ move setter 校验后交给 SLM，避免复制整幅计算结果。取消、失败或过期结果不覆盖已有相位；SLM 分辨率修改仍按原规则清空不匹配数据。数值循环已经异步，但快照、相位校验、灰度转换和纹理上传仍在 game thread，大分辨率预览仍可能消耗帧时间，不能据此宣称整个 UI 更新无停顿。

Workbench 新增可选 `Solver` 引用、**Solve Phase Pattern** / **Cancel Solve** 按钮及状态镜像。Solve 会给尚未绑定的 Solver 指定当前 Workbench，不覆盖已经绑定的其他 Workbench。作业和缓冲始终归 Solver Actor 管理；Workbench 负责快照与用户命令入口。Docker 枚举目前明确返回未实现错误，没有创建网络客户端或进行 TCP 通信。

Solver 的 **Save Phase Pattern** / `SaveGeneratedPhasePattern()` 只允许保存处于 `Ready`、仍保存在同一个发布目标 SLM 上、相位版本未变的最后一次计算结果。排队/运行中、SLM 被替换、相位被清除或后续发布改变相位版本时拒绝保存，避免把另一幅相位误认为本次计算结果。SLM 自身的 **Save Phase Pattern** / `SaveCurrentPhasePattern()` 可以保存任意当前有效相位，包括手动输入、已加载资产和预览斜坡。

### 15.2 原始文件格式与边界

`.bin` 为无文件头的 **little-endian IEEE-754 float64 弧度数组**，完全保留存储数值，不转灰度、不量化；行优先 `PhaseRad[row * ResolutionX + column]`，长度为 `8 * ResolutionX * ResolutionY` 字节。column 增加沿 SLM 局部 +Y，row 增加沿 -Z。配套 UTF-8 `.json` 记录分辨率、以米为单位的像素间距、布局/轴约定、来源标签和 preview 标志；其中 `coordinate_frame="SLM-local"`、`pixel_center_convention="centered"`、`optical_normal_slm="+X"`、`pixel_plane_x_m=0` 明确采用第 13 节的居中像素公式，不导出 SLM 世界变换。元数据描述的是当前相位缓冲及物理网格，不声称存档了原始目标、波长或完整求解请求；测试斜坡仍标识为 preview。

外部 NumPy 可按匹配 JSON 中的网格尺寸读取：`numpy.fromfile(binary_path, dtype="<f8").reshape(resolution_y, resolution_x)`。上述二进制输出保持完整精度；另存的 PNG 按第 15.4 节映射为 8 位灰度。

保存功能只在 Editor 中提供持久化；Game 构建返回不支持状态。显式保存的资产序列化和文件操作是同步的，大分辨率可能耗时；这不改变 CPU 数值求解的异步机制。

### 16.1 复数场与权重

对每个 SLM 像素 `p`，先累加所有点的复数场，再提取一个相位；不能直接累加相位角：

```text
r_j = length(q_j - p)
F(p) = sum_j a_j * exp(i * (phi_j - k*r_j))
phi_inc(p) = InitialPhaseRad + k*dot(DirectionSLM, p)
phase_slm(p) = wrap_[0,2*pi)(atan2(Im(F), Re(F)) - phi_inc(p))
```

传播仍为 `exp(+i*k*r)`，像素坐标、行列方向和 PlaneWave 入射补偿保持第 13、14 节约定。数值实现先计算每个点的加权相量 `a_j*exp(i*phi_j)`，再乘 `exp(-i*k*r_j)`，避免较大的传播相位抹去点之间较小的相位差。单个正振幅 Point 目标退化为原有聚焦公式；多点结果是复场的 phase-only 编码，不承诺每个目标的重建强度精确满足输入，也不消除点间串扰。

Point 目标使用描述中的位置、振幅、相位。Mesh 点的位置变换为 `TargetDescription.PositionSLMM + TargetDescription.RotationSLM.RotateVector(Point.PositionLocalM)`。点资源已经使用米、烘焙 Actor/组件缩放和组件偏移，并已继承目标振幅/相位；求解器只使用每点权重一次，不再乘目标振幅、不再加目标相位、不再施加缩放。没有 `1/r`、法线/UV 权重或按单个 Mesh 点数归一化；采样更密会增加相同权重的发光点数量。

所有点振幅必须有限且非负，零振幅不贡献复场；全局全零输入失败。正振幅点须位于 SLM 平面外，Mesh Actor 原点可在平面上，只要实际贡献点的局部 X 不为零。对所有振幅统一除以最大值，避免大权重求和溢出且不改变相位；实部与虚部分别使用 Neumaier 补偿求和减少舍入误差。当某像素复场模长不超过 `32 * double_epsilon * sum(normalized_amplitudes)`，视为数值相消，直接令该像素 **SLM 相位为 0**，不再减入射相位。该确定性回退不代表 phase-only SLM 能在此产生零振幅。

光源 Amplitude 与 PolarizationAngleRad 继续接受和校验但不影响标量结果；目标振幅现在参与复场叠加并触发自动更新。暂不增加传播图、偏振模型或传感器模拟。

### 16.2 资源、异步与使用

Workbench 的 Targets 列表可加入多个不同的 Point/Mesh Actor；全部须有效、位于同一 World、使用同一个 SLM。重复 Actor、缺失引用、无效/空点云、描述与资源的 ID/版本不匹配均失败。所有 Point 项加 Mesh 点数的输入总量最多为 **1,000,000**，包含零振幅项，以限制快照大小。

常规输入捕获与 Tick 比较只读取描述、引用和资源版本；真正启动任务时才复制所需点云。worker 持有不可变纯数据，不访问 Actor/UObject。目标列表、位置/振幅/相位、Mesh 变换/采样和资源版本参与 Auto Solve 与过期结果判断；新请求继续替换唯一最新待处理请求，并取消旧任务。发光点累加内循环也检查取消，避免稠密点云必须计算完整行后才响应。

使用方式仍是 **CPU / PointFocus → Generate Phase Pattern → Ready → SLM 预览**；Auto Solve 可选，默认关闭。Mesh 的 **Resources Valid**、**Point Count** 和 **Show Point Cloud** 可用于确认求解样本。先使用较小 SLM 网格与较粗 Slice Count / Point Spacing：复杂度为像素数乘正权重点数。点云更新/复制、输出校验和预览上传仍在 game thread，并不保证所有编辑器操作完全无停顿。

显式 Save 按钮继续保存匹配的 `.uasset`、`.bin`、`.json` 和像素一一对应的灰度 `.png`；Generate/Auto Solve 不自动写盘。当前用户设置的原生网格默认值为 256×256、8 µm，对应 2.048×2.048 mm；旧章节中 4096×4096 的测试和性能数字是历史记录。无需重建或另存已有 Blueprint/地图。
